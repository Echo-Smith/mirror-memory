- 迁移**第 7 步**（LATEST_VERSION=7）：三表 NOT NULL VARCHAR(64)，PG 走 ADD COLUMN → 批量回填 → NOT VALID CHECK / VALIDATE / SET NOT NULL → SET DEFAULT ''；SQLite ADD COLUMN NOT NULL DEFAULT '' 后批量回填。可选参数就是第 6 步的 `legacy_job_purpose` / `MM_LEGACY_JOB_PURPOSE`（共享解析器 `_legacy_purpose_value`）：一个选择同时标注存量任务与存量记忆；服务端默认值恒为 `''`，legacy purpose 只标注已存在的行、重入时补标仍是 `''` 的行。无新表：RLS 姿态、写入守卫类别、system_scope 使用点全部不变。

LIMIT batch)` 匹配（仍是绑定参数），新增 `marker` 参数；SQLite 与 PG 各有测试（含整步 6 对模拟 v5 的 PG schema 的运行）。这不是隔离 / 授权漏洞（fail-closed：升级会失败而不是静默），故未停下整体工作。

**任务 3——export / explain**（`81804b3`）
- `MemoryEngine.export_page / export` + `GET /export`，格式 **mm-export/1**：beliefs → evidence → events 三个 section 固定顺序、按 id 升序 keyset 分页（不透明游标 `<section>:<last_id>`，末页 None）；证据与事件带 `source_purpose`，信念带 `source_purposes`（其证据链接的来源集合，与 explain 的推导一致）；每页带 `revision`（读取时的记忆状态修订号）与 `authorization {purpose, grant_version}`。

## 四、export 格式与 v2 差异表

| 维度 | v2 `export` | v1 `export`（本批） |
|---|---|---|
| 形态 | 异步：`ExportOutput(status, download_url="receipt://<id>", expires_at)`，交付前再验权，临时文件到期清理 | 同步流：逐页返回，`export_page(cursor, page_size)` / `export()` 生成器 / `GET /export?cursor=` |
| 内容 | 不含数据（只回执：evidence_count / memory_count / auth_version） | 真数据：beliefs + evidence + events，含 source_purpose（信念为推导集合） |
| 格式版本号 | 无 | `schema_version: "mm-export/1"` |
| 范围 | `scope: "all" / "evidence" / "memories"` | 固定三 section 全量（分页内天然可截断） |
| 授权 | `_check_auth(context, "export")` 一次 | 每页 `authorize(user, purpose, "export")`；中途撤销 → 下一页拒绝（有测试） |
| 一致性 | 文件级快照 | 非快照；每页带 `revision` 供检测 |
| 审计 | receipt 行 | 每页一行访问审计（ids + 截断标记） |
| 内容红线 | 排除令牌与内部秘密 | 不含授权行 / 审计行 / 凭证；证据与信念文本是导出目的本身 |
| 租户 | scope 对象 | 复合租户键，tenant(app) 引擎 |
