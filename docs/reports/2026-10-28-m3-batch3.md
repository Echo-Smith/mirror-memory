## 二、各任务设计决定与证据

**任务 1——跨用途可见性（A2）**（`8bc7859`）
- `core.provenance.visibility(session, user_id, purpose)`：一次 SELECT 取该用户当前有效 purpose 集（未撤销、未过期，与 authorize 同判据、扩到全部 purpose），在调用方事务内执行——无跨事务缓存，撤销已提交即对下一次请求生效。`VisibilityRule.purpose_visible()`：`''` 在全局开关开时可见（所有消费方都跑在 authorize 之后，authorize 已验过开关，故产品路径恒可见；测试直接锁 off 分支）。
- **信念可见规则**（批量两查 + Python 判定，沿用 list 函数既有的「limit 后过滤」模式）：有证据链接 → 任一链接证据的 `source_purpose` 可见；无链接 → 只看 created / corrected 两类事件；其他事件（supported / confirmed / worker 发布）**永不算出处**——「P 独有证据的信念有一条 Q 事件，P 撤销后在 Q 下仍不可见」有专门测试锁住。**既无链接也无 created/corrected 事件**的信念（直接播种、M3 前形态）按空标记处理（全局开关开即可见）；有出处但全部不可见的信念仍然隐藏——`''` 的兜底只给「从未记录出处」的行，不给「出处被撤销」的行。
- **接入面**（任务书四路径 + 零泄漏验收倒逼的追加，均写明）：recall_candidates（在单值槽逻辑**之前**过滤——不可见的新信念不得压掉同槽可见的旧信念）、list_active_beliefs、explain_belief（不可见 = None，不泄漏存在性；可见则证据 id/图/事件只列可见出处，**压缩摘要在任一链接证据不可见时整体隐去**——digest 折叠的文本可能来自被撤销 purpose）、belief_history（不可见 → []）、验证候选（问题会引用 claim 文本）、export 三段（信念按规则、证据/事件按各自 source_purpose；keyset 游标按**取回的行**推进，被扣留的行只会让页变小、不会错位）、server 的 belief_by_id（不可见 = 404，与跨租户同形态）、**worker**（`_load_evidence` 按规则过滤、distinct_sessions 数可见页——影子门问的是「本作业的 purpose 见过几个会话」；K3 的信念上下文同步过滤）。
- **追加：会话摘要回退**。recall 的 snippet fallback 返回**原始消息文本**——它和证据一样是出处，但 `mm_session_summaries` 没有来源列。第 9 步给它补 `source_purpose`（observe 写入时盖章、首次收集为准），回退按规则过滤。这是任务书四路径之外的第 5 个泄漏面，由场景推演发现并堵上。
- **快照方案（二选一，选了 (a) 的读时门控、快照粒度）**：先枚举了全部快照读路径——v1 **没有面向调用方的快照读 API**（api/server 均不返回快照内容），唯一读快照的是 worker K3 的两处内部上下文读取（`_get_slice_summaries`、`_get_current_understanding`）。据此：(a) 原文「要求所含信念全部可见」**无法结构性执行**——快照 content 是自由文本合成物，没有信念 id 映射；(b)「撤销时作废」需要授权模块写内容表 + 对过期授权的主动清扫。**实现：读时按快照自身的 source_purpose（合成它的作业 purpose）校验**，不通过即视为不存在（不回退到更旧的版本），下个完成作业重建——效果与 (b) 相同（陈旧快照被跳过并重建），但零新增写路径、撤销即时、有测试锁定。

## 三、快照方案的选择（任务书要求单列）

**选择：(a) 读时门控，快照粒度**（而非 (b) 撤销时作废重建）。

- 快照读路径枚举：v1 无面向调用方的快照读；唯一读者是 worker K3 的两处内部上下文读取。
- (a) 原文（逐信念判定所含信念）不可执行：content 是自由文本合成物，无信念 id 映射。
- (b) 的代价：授权模块获得写内容表的路径 + 过期授权需要主动清扫（撤销能写、过期谁来写？）。
- 折中实现的效果与 (b) 等价：读时校验快照自身的 `source_purpose`（合成作业的 purpose），不通过即跳过（不回退旧版本），下个完成作业重建。撤销即时、无缓存、零新增写路径，测试锁定。

## 四、与任务书不同的决定（汇总）

1. 快照方案取 (a) 的读时门控（见第三节）。
2. 可见性接入面超出四个函数：belief_history、验证候选、worker 证据/K3、server belief_by_id、会话摘要回退——由「撤销后全路径哨兵零泄漏」的验收要求倒逼，逐一列明。
3. 无任何出处的信念按 `''` 处理（可见随全局开关），而非一概不可见——与批 2 的空标记语义一致；有出处但全不可见的仍隐藏。
4. correct / restore 未按可见性过滤（任务未列，行为改变风险大）：correct 需要调用方已知 belief_id，且 id 无法从过滤后的读路径获得——残余为一个需要猜测 id 的内容 oracle，记录为已知风险，建议下一批处理。forget 路径按设计不过滤（删除必须无条件可用）。list_rejected_beliefs 未过滤（用户自划边界、仅出标签）。
5. 审计维护的租户枚举引入 1 个新 system_scope 使用点（任务书允许，单独列出待评审）。
